# 1係 KPIダッシュボード

営業1係向けのKPI可視化＋報告作成アプリ。Google Sheetsをデータの正としたまま、「誰の分を見るか × 何を見るか」の2階層で切り替えて閲覧・入力できる。

公開URL: https://masuda15k.github.io/kpi-dashboard/

## 画面構成

**レベル1／表示対象（塗りピル）**
`1係全体` `菅原` `丸野` `江波戸` `飯山`

**レベル2／タブ（下線タブ）**
`ダッシュボード` `日報` `週報` `月報` `分析`

**レベル3／分析タブ内のみ（セグメント切替）**
`全般` `架電分析` `商談分析`

階層を見間違えないよう、L1/L2/L3で操作部品の見た目そのものを変えている。対象によって出せないタブは自動的に隠れる。

- `月報` … 1係全体のみ（メンバー個人タブに月報転記ブロックが存在しないため）
- 分析の `全般` … 1係全体のみ（セグメント別転換率・失注理由・滞留案件・データ品質は係全体の指標）

## 構成

- `index.html` … 全機能を含む単一ファイル（Vanilla JS、外部フレームワーク不使用）
- `.gitignore` … 認証情報ファイルの誤コミット防止

依存ライブラリはなし。`https://accounts.google.com/gsi/client`（Google Identity Services）と Google Sheets API v4 をブラウザから直接叩く。

## 使い方

1. 公開URL（`file://` ではなく https://masuda15k.github.io/kpi-dashboard/ ）を識学Googleアカウントで開く
2. 「Googleでログイン」→ 認証（社外アカウント不可）
3. ログイン直後は自分の担当分が開く（メンバーは自分、増田係長・その他は1係全体）
4. L1で表示対象、L2でタブを切り替える。閲覧は全対象・全員に開放、**入力は本人の対象のみ**
5. 一度サインインしたブラウザでは、再訪問時に自動サインインを試みる

## データマップ

参照先スプレッドシートは `index.html` の `SPREADSHEET_ID`。各タブは `■`／`◆` 見出しで区切られており、**セクションの行番号はメンバーごとにズレる**（例：`■4` が46/47/43/48行目）ため、必ず見出し文字列で解析している。行番号のハードコードはしない。

| レベル2タブ | 1係全体 | メンバー |
|---|---|---|
| ダッシュボード | `ダッシュボード`タブ：■①ゴールとのギャップ／■①'前Q同時点比較／■②ファネル／■③メンバー別ペース／■④今週のアクション／■⑤データ品質／■グラフ用データ | 本人タブ：■1目標対比／■2ファネルと転換率(本人vs係平均)／■3パスした案件のその後／■4週次トレンド／■5先行在庫と必要自アポ |
| 日報 | `報告` B4:B6 ＋ ◆日報の生成済みテキスト | 本人タブ B4:B9 ＋ ◆日報の生成済みテキスト |
| 週報 | `報告` B7:B14 ＋ ◆週報の生成済みテキスト | 本人タブ B10:B17 ＋ ◆週報の生成済みテキスト |
| 月報 | `報告` B15 ＋ ◆月報転記ブロック | なし（タブを隠す） |
| 分析 > 全般 | `分析` ■1セグメント別転換率／■2失注理由／■4滞留案件／■5データ品質 | なし（セグメントを隠す） |
| 分析 > 架電分析 | `分析` ■3 活動相関（週次：架電→アポ） | 本人タブ ■6（架電数(Q)／本人接続／接続率／アポ獲得／架電→アポ率） |
| 分析 > 商談分析 | `分析` ■6 商談分析（担当別の採点表） | 同じ ■6 を `担当` 列で本人のみに絞り込み |

未知の見出しはテーブルとしてそのまま描画されるため、スプシ側にセクションが増えても壊れない。

## 設定（`index.html` 内の定数）

| 定数 | 内容 |
|---|---|
| `CLIENT_ID` | Google OAuthクライアントID。GCPプロジェクトの承認済みJavaScriptオリジンに公開URLを登録しておく必要がある |
| `SPREADSHEET_ID` | データソースのスプレッドシートID |
| `SHEET_DASHBOARD` / `SHEET_REPORT` / `SHEET_ANALYSIS` | 参照するタブ名（`ダッシュボード`／`報告`／`分析`） |
| `MEMBERS` | 個人タブを持つメンバー（L1ピルの表示順） |
| `MEMBER_MAP` | ログインメールアドレス → `{tab, label}`（書き込み先タブ名と画面表示名）。ここに登録のない人は全対象が閲覧専用になる |
| `MEMBER_MANUAL_CELLS` | メンバー個人タブの入力項目定義。`B4:B17`（14項目）と1対1対応 |
| `REPORT_MANUAL_CELLS` | `報告`タブの入力項目定義。`B4:B15`（12項目）と1対1対応。項目数もラベルもメンバー用とは別物 |

**入力欄がどの報告タブに出るかは、ラベルの `【日次】`／`【週報】`／`【月報】` 接頭辞から自動判定される**（`groupOfLabel`）。書き込み範囲も定義配列の位置から `inputGroupFor` が計算するため、項目を増減してもセル範囲を手で直す必要はない。スプシ側の開始行・列そのものを変える場合のみ `inputGroupFor` を修正する。

## 認証・セッションまわりの挙動

- Google Identity Services のトークンクライアント方式（`initTokenClient` + `requestAccessToken`）
- 初回は `prompt: 'consent'` で明示的にログインボタンを押してもらう
- アクセストークンの有効期限の5分前に `prompt: ''`（サイレント）で裏側だけで自動更新する。失敗（Google側セッション切れ等）でログイン画面に戻す
- 再訪問時は `localStorage`（`kpiDashboardAutoSignIn`）に「前回サインイン済み」の事実だけを記録し、読み込み時にサイレント再認証を試みる。**アクセストークン自体はどこにも保存しない**（XSS等での漏えいを避けるため）
- 明示的なログアウトでこのフラグを消し、次回は通常のログインボタンから開始する

## データ取得の方針

- 必要なタブを `values:batchGet` で**1リクエストにまとめて取得**する
- 1係全体＝`ダッシュボード`＋`報告`＋`分析`、メンバー＝本人タブ＋`分析`
- 一度読んだタブは `sheetCache` に保持し、表示対象を切り替え直してもAPIを再実行しない
- 入力欄の現在値もタブ全体の取得結果から引くため、フォーム表示のための追加リクエストは発生しない
- 保存に成功したときだけ、そのタブのキャッシュを破棄する

## 既知の制約

- `file://` で直接開くとOAuthの許可オリジンが一致せず必ず認証エラーになる（公開URLへの案内を表示するのみ）
- 棒グラフの系列色は固定8色パレットまで（dataviz skillのカテゴリカルパレット準拠）。9系列目以降はグレーにフォールバック
- **スプレッドシート側の要修正**：メンバータブ ■1 目標対比の一部セルが日付シリアル値に化けている（例：`46218`）。`5/16` のような「x/y」表記をGoogle Sheetsが日付として自動解釈した結果で、API経由では元の表記を復元できない。`kpi-sheets-v3.js` 側で文字列として書き込む（`'` 付与または書式をテキスト固定）修正が必要。アプリ側は該当セルに「要確認」の印を付けるのみ
