# 1係 KPIダッシュボード

営業1係向けのKPI可視化ダッシュボード。Google Sheets上の実績データをそのまま読み込み、ゴール達成率・ファネル・メンバー別ペース・アクション/警告・グラフとして表示する。メンバー4名（菅原・丸野・江波戸・飯山）は自分の日次/週次実績を、係長（増田）は係全体の日報・週報・月報（「報告」タブ：不足の理由・行動変化等）を、このページから直接入力できる。

公開URL: https://masuda15k.github.io/kpi-dashboard/

## 構成

- `index.html` … 全機能を含む単一ファイル（Vanilla JS、外部フレームワーク不使用）
- `.gitignore` … 認証情報ファイルの誤コミット防止

依存ライブラリはなし。`https://accounts.google.com/gsi/client`（Google Identity Services）と Google Sheets API v4 をブラウザから直接叩く構成。

## 使い方

1. 公開URL（file://ではなく https://masuda15k.github.io/kpi-dashboard/）をGoogle社内アカウントで開く
2. 「Googleでログイン」→ 識学Googleアカウントで認証（社外アカウント不可）
3. タブ「概要」「メンバー」を閲覧。`MEMBER_MAP`に登録された5名（メンバー4名＋増田）のみ「入力」タブが表示され、本人の実績（またはメンバー4名の場合は個人タブ、増田の場合は「報告」タブ）を入力・保存できる
4. 一度サインインしたブラウザでは、再訪問時に自動でサインインを試みる（Google側のセッションが有効な間はボタン操作不要）

## 設定（`index.html` 内の定数）

| 定数 | 内容 |
|---|---|
| `CLIENT_ID` | Google OAuthクライアントID。GCPプロジェクトの承認済みJavaScriptオリジンに公開URLを登録しておく必要がある |
| `SPREADSHEET_ID` | データソースのスプレッドシートID |
| `SHEET_RANGE` | 概要データを読むタブ名（`ダッシュボード`） |
| `MEMBER_MAP` | ログインメールアドレス → `{tab, label}`（本人入力用シートタブ名と、画面表示用の呼び方）。ここに登録のない人は自動的に閲覧専用になる |
| `MEMBER_MANUAL_CELLS` | メンバー4名の入力フォーム項目定義。各個人タブの `B4:B17`（14項目）と順序が1対1で対応する |
| `REPORT_MANUAL_CELLS` | 増田用「報告」タブの入力フォーム項目定義。`B4:B15`（12項目）と順序が1対1で対応する。メンバー用とはラベル・項目数が異なる別定義 |

入力欄の行範囲（`B4:Bxx`）は`manualCellsFor(tab)`が返す項目数から自動計算される（`3 + 項目数`）ため、項目を増減した場合はセル位置の指定を変える必要はない。スプシ側のセル「位置」自体（開始行や列）を変える場合のみ、`inputRangeFor`を修正する。

## スプレッドシートのデータ構造

`SHEET_RANGE`（`ダッシュボード`タブ）の1列目にある `■` プレフィックスの見出しでセクションを自動判定して描画を出し分ける。未知の見出しはテーブルとしてそのまま表示するため、見出しを増やしても壊れない。

| 見出し | 内容 | 描画 |
|---|---|---|
| （先頭の非■行） | タイトル／期間（「Q(6/1〜8/31) 29/64営業日(45%)」等） | ヒーロー＋四半期経過率リング |
| `■①` | ゴールとのギャップ（実績/MUST/達成率/ペース/着地見込み/過不足/補足） | 指標タイル＋位置トラック |
| `■②` | ファネル（件数と転換率の交互列） | ファネル図 |
| `■③` | メンバー別ペース | メンバーカード＋進捗バー（★members panelに描画） |
| `■④` | 今週のアクション | 色分けリスト |
| `■⑤` | データ品質警告 | 注意バナー |
| `■ グラフ用データ` | 空行区切りのグループごとに `[カテゴリ列, 系列名...]` | 棒グラフ（系列は最大8色まで固定パレット、それ以降はグレー） |
| `■ グラフ（...` | Sheets埋め込みグラフへの案内行 | 無視（HTML側で実グラフを描くため不要） |

ペース欄などの絵文字（🔴🟡🟢）で状態色（critical/warning/good）を判定する。

## 認証・セッションまわりの挙動

- Google Identity Services のトークンクライアント方式（`initTokenClient` + `requestAccessToken`）を使用
- 初回は `prompt: 'consent'` で明示的にログインボタンを押してもらう
- 取得したアクセストークンの有効期限の5分前に、`prompt: ''`（サイレント）で自動的に裏側だけで更新する。失敗した場合（Google側セッション切れ等）はログイン画面に戻す
- 再訪問時は `localStorage`（`kpiDashboardAutoSignIn`）に「前回サインイン済み」の事実だけを記録し、ページ読み込み時にサイレント再認証を自動で試みる。アクセストークン自体はどこにも保存しない（XSS等でのトークン漏えいリスクを避けるため）
- 明示的にログアウトした場合はこのフラグを消し、次回訪問時は通常のログインボタンから開始する

## デプロイ

`main` ブランチへの push で GitHub Pages（`https://masuda15k.github.io/kpi-dashboard/`）に反映される。単一HTMLファイルのため、ビルド手順は不要。

## 既知の制約

- `file://` で直接開くとOAuthの許可オリジンが一致せず必ず認証エラーになる（公開URLへの案内メッセージを表示するのみ）
- 棒グラフの系列色は固定8色パレットまで（dataviz skillのカテゴリカルパレット準拠）。9系列目以降が来た場合はグレー表示にフォールバックする
